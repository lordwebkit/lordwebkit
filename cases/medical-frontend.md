# Frontend медицинской информационной системы

[← К профилю](../README.md)

Разработка интерфейсов для врачей, персонала и администраторов: от карты пациента
и протокола приёма до справочников и структуры организаций.

**Моя роль:** frontend-разработка в команде, интеграция с существующим API,
проверки пользовательских сценариев. Серверную часть системы разрабатывала
другая часть команды.

**Стек:** Nuxt 4, Vue 3, TypeScript, Pinia, Tailwind CSS, vee-validate, Zod,
Vitest, Playwright.

## Задача

Связать несколько рабочих сценариев в одном интерфейсе. Пользователь должен
видеть актуальные сведения, заполнять формы, понимать ошибки и продолжать работу
при изменении данных на сервере.

## Мой вклад

- Интегрировал интерфейс карты пациента, историю событий и данные приёмов с API.
- Реализовал frontend-сценарии ведения протокола приёма, назначений и направлений.
- Разрабатывал формы и деревья структуры организаций: создание, просмотр,
  редактирование и фильтрацию объектов.
- Дорабатывал общие механизмы валидации, отображения ошибок и защиты от повторной
  отправки формы.
- Добавлял модульные и браузерные проверки форм и интеграционных сценариев.

## Инженерные решения

**Разделение общего и прикладного кода.** Работал в монорепозитории с клиентским
приложением, админкой и общим Nuxt Layer. Общие API-типы и механизмы интерфейса
переиспользуются между приложениями; код отдельного сценария остаётся в его модуле.

**Формы как отдельный сценарий.** Подготовка данных, валидация и преобразование
значений для API вынесены из шаблонов. Ошибки сервера сопоставляются с полями,
а пользователь получает понятное состояние отправки и возможность исправить ввод.

**Конкурирующие запросы и изменения.** Зависимые списки учитывают отмену загрузки,
чтобы старый ответ не подменял актуальный выбор. При сохранении учитывается версия
записи; конфликт с серверным состоянием обрабатывается отдельно от ошибок ввода.

## Проверки

В моих изменениях есть тесты на преобразование данных протокола, обязательные поля,
конфликты версий, зависимые списки, периоды действия и повторное сохранение форм.
Браузерные сценарии дополняют проверки логики.
